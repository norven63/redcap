## 弱共识行动（2/4 支持）

1. `prism-archive-check.sh` 必须至少以 `prism/reports/.session-registry.yaml` 为 quorum 的唯一数据源；本轮实现进一步把 `schema_ok`、`injection_mode`、lingering `dispatched` 状态一并纳入 gate。（reviewer + historian；其中后 3 项为本轮实现加固）
2. Collect 阶段对“backend 支持追问”的判定必须收紧为：**有 handle + 有续接模板 + 本轮保留 session 信息**，不能把 CLI 的理论 `--resume` 能力直接等同于 `supports_follow_up=true`。（challenger + reviewer）
3. Dispatch preflight 必须显式携带/校验 `injection_mode` 计划；`session_registry` 中 `handle / injection_mode / status / schema_ok` 的写回责任必须由 Cap / Dispatcher 明确承担。（challenger + reviewer）

## 单点但已采纳修复

1. 所有 redteam 角色强制增加“机制空缺审计”：凡文档声称机制存在、但没有 HOW / 没有执行闸门，必须显式报出。（historian，命中 L-34）
2. Collect 协议显式改为“先高容错提取 JSON，再决定是否追问/标 absent”；不再假设 stdout 天然是干净 JSON。（historian + 本轮实测输出）

## 已知限制 / OPEN_QUESTIONS
