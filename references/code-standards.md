# 代码规范

## 通用规范（所有语言/框架必须遵守）

### 1. 命名规范
- 禁止使用 1-2 个字符的变量名（循环变量 `i`、`j` 除外）
- 变量名、函数名必须具有明确的语义，优先使用完整单词而非缩写
- 函数/方法名应为动词或动词短语，变量名应为名词或名词短语
- 使用有意义的变量捕捉复杂条件或中间计算结果的含义

### 2. 模块拆分原则
- 单文件代码量 ≤ 500 行时，允许保持单文件结构
- 单文件超过 500 行时，应按职责拆分为独立模块
- 拆分粒度以"职责清晰、内聚性高"为原则，避免过度设计
- 具体的模块组织方式应遵循所选技术栈的社区惯例

### 3. 错误处理
- 禁止空的 try/catch（或等价的异常捕获结构），捕获异常后必须有意义地处理
- 优先使用守卫子句 / 提前返回，先处理错误和边界情况
- 避免超过 2-3 层的深层嵌套

### 4. 注释规范
- 禁止为显而易见的代码添加注释
- 类和关键公共函数必须有文档注释（docstring / Javadoc / JSDoc 等）
- 注释应解释"为什么"而非"怎么做"
- 禁止遗留 TODO 注释，应直接实现或明确记录到任务管理中

### 5. 代码风格
- 新代码必须与项目已有代码风格保持一致
- 优先使用多行表达式，避免过长的单行代码或复杂的三元表达式
- 不要重新格式化与当前修改无关的代码

### 6. 依赖管理
- 项目必须包含依赖声明文件（如 requirements.txt / package.json / pom.xml / go.mod 等）
- 引入新依赖前应评估必要性，避免引入过重或不活跃的第三方库

## 语言/框架特定规范

以上通用规范适用于所有项目。除此之外，开发时还应遵循所选技术栈的社区最佳实践和官方推荐的代码风格规范，例如：
- Python 项目遵循 PEP 8
- Java 项目遵循 Google Java Style 或团队约定
- JavaScript/TypeScript 项目遵循 ESLint 推荐规则
- Go 项目使用 gofmt 格式化

具体适用哪套语言规范，依据《技术栈选型》文档中确定的技术栈来判断。
