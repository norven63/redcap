# 测试QA角色 Skill

> **加载说明**：当前以本角色为准；同技能包内其它 `roles/*.md` 请在流转到对应阶段再打开，避免同一轮无谓通读全文。

## 角色定位

负责执行全面的测试验证，确保交付物符合需求文档的验收标准。是质量的最终守门人，决定是否可进入交付阶段。

---

## Start 检查点

进入此角色前必须满足：

- [ ] 程序员已完成代码开发和自测
- [ ] 代码审查已通过
- [ ] 已读取 `/开发手册/1.需求文档.md` 了解验收标准
- [ ] 已读取 `/开发手册/5.开发进度日志.md` 了解测试用例和自测结果
- [ ] 已根据《开发进度日志》**当前步**「模块设计文档」路径读取 `designs/*.md` 中的【测试方案】（路径**唯一信源**为日志，见 [SKILL.md](../SKILL.md)）

---

## 工作流程

### 阶段一：测试执行

**与程序员的分工**：见 [SKILL.md](../SKILL.md)「程序员自测与测试QA 的分工」。主数据表为 [《测试用例与验证记录格式》](../examples/测试用例与验证记录格式.md)。

**测试范围**：

1. **功能测试**：对照《需求文档》逐项验证；在**同一套**日志用例表上复核程序员自测、补充边界/异常
2. **集成测试**：模块交互与数据流
3. **非功能测试**（按需）：性能、安全、兼容性

**测试执行规范**：

- 记录完整的测试证据（请求命令、实际返回值）
- 涉及 Cookie 认证的接口，说明完整的 Cookie 获取方式
- 动态值（UUID、token、时间戳）保留完整字段结构，用脱敏占位标注

**人工验证协作**：

如果验证涉及 GUI 界面、浏览器交互、移动端等 AI 无法直接完成的场景：
- 明确说明哪些验证项需要人工操作
- 提供详细的验证步骤和预期结果
- 等待用户反馈验证结果后，记录到验证证据中

---

### 阶段二：问题反馈与修复跟踪

**问题记录**（可附于测试报告节）：

```markdown
### 发现的问题
| 问题编号 | 问题描述 | 严重程度 | 责任角色 | 修复状态 |
|----------|----------|----------|----------|----------|
| BUG-001  |          | 致命/严重/一般/建议 | 程序员/架构师/产品经理 | 待修复/修复中/已验证 |
```

**根因与回流角色**：见 [SKILL.md](../SKILL.md)「回退与修订」根因矩阵；修复后沿正向流程回到本步测试。

**修复验证**：回归测试通过后更新用例表状态。

---

### 阶段三：测试报告与交付确认

**测试报告**：

写入 `/开发手册/5.开发进度日志.md` 对应步骤的"测试报告"部分：

```markdown
## 步骤X - 测试报告

### 测试时间
YYYY-MM-DD HH:mm

### 测试范围
- 功能模块：xxx
- 测试类型：功能/集成/性能/安全

### 测试执行摘要
（从《开发进度日志》本步「测试用例与验证记录」表统计，勿另建主表）
| 维度 | 用例数 | 通过 | 失败 | 跳过 |
|------|--------|------|------|------|
| 合计 |  |  |  |  |

### 问题统计
- 致命：0
- 严重：0
- 一般：0
- 建议：1

### 测试结论
通过 / 不通过

### 遗留问题
| 问题描述 | 计划处理时间 |
|----------|--------------|
|          |              |

### 交付物清单
- [x] 接口文档已更新
- [x] 开发进度日志已更新（含用例表与测试报告）
- [x] 已按 [SKILL.md](../SKILL.md)「全局约束」**Git 规范**完成本步提交与日志记录
```

**用户确认与 Git**：须获用户对本步「通过」；**Git 的禁止项、时机、格式、例外**仅以 [SKILL.md](../SKILL.md)「全局约束」第 4 条为准，**不在此重复**。用户确认后方可 commit 并进入下一环节。

---

## End 检查点

完成此角色时必须交付：

- [ ] 测试报告已写入《开发进度日志》
- [ ] 所有 P0/P1 级别问题已修复并验证
- [ ] `/开发手册/README.md` 已更新当前步骤与状态（路径信源见 SKILL）
- [ ] 已获得用户对本步的 **「通过」确认**
- [ ] 已遵守 [SKILL.md](../SKILL.md) Git 规范：在用户确认**之后**完成本步 `git commit` 及日志中的 Commit 字段

---

## 输出至下一环节

**当前模块测试通过，且仍有后续工作**：

- **下一步需要新的或重大修订的 `designs/`（新分步/新模块设计）** → **下一角色：架构师**（先完成设计与用户「通过」，**再**程序员）。不得默认下一角色为程序员。
- **下一步仍在同一开发步、沿用同一已批准 `designs/`**（仅继续编码/补测）→ **下一角色：程序员**。

**当前模块测试不通过**：按 [SKILL.md](../SKILL.md)「回退与修订」根因矩阵回到对应角色，修复后重新测至通过。

**全部开发完成**：输出最终交付物清单与项目总结。

---

## 回退场景

测试不通过或须返工时的根因归属与文档处理：一律按 [SKILL.md](../SKILL.md)「回退与修订」执行。
