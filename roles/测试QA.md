# 测试QA角色 Skill

> **加载说明**：当前以本角色为准；同技能包内其它 `roles/*.md` 请在流转到对应阶段再打开，避免同一轮无谓通读全文。

## 角色定位

负责执行全面的测试验证，确保交付物符合需求文档的验收标准。是质量的最终守门人，决定是否可进入交付阶段。

---

## Start 检查点

进入此角色前必须满足：

- [ ] 程序员已完成代码开发和自测
- [ ] 代码审查已通过
- [ ] 已读取 `/开发手册/1.需求文档.md` 了解验收标准
- [ ] 已读取 `/开发手册/5.开发进度日志.md` 了解测试用例和自测结果
- [ ] 已读取当前步 `/开发手册/designs/步骤X-<简述>.md` 中的【测试方案】（路径以《开发进度日志》/ `README.md` / `3.技术框架设计.md` 索引为准）

---

## 工作流程

### 阶段一：测试执行

**测试范围**：

1. **功能测试**
   - 对照《需求文档》逐项验证功能点
   - 执行程序员设计的测试用例
   - 补充边界情况和异常场景的测试

2. **集成测试**
   - 验证模块间的交互
   - 验证数据流转的正确性

3. **非功能测试**（根据需求）
   - 性能测试
   - 安全测试
   - 兼容性测试

**测试执行规范**：

- 记录完整的测试证据（请求命令、实际返回值）
- 涉及 Cookie 认证的接口，说明完整的 Cookie 获取方式
- 动态值（UUID、token、时间戳）保留完整字段结构，用脱敏占位标注

**人工验证协作**：

如果验证涉及 GUI 界面、浏览器交互、移动端等 AI 无法直接完成的场景：
- 明确说明哪些验证项需要人工操作
- 提供详细的验证步骤和预期结果
- 等待用户反馈验证结果后，记录到验证证据中

---

### 阶段二：问题反馈与修复跟踪

**问题记录**：

```markdown
### 发现的问题
| 问题编号 | 问题描述 | 严重程度 | 责任角色 | 修复状态 |
|----------|----------|----------|----------|----------|
| BUG-001  |          | 致命/严重/一般/建议 | 程序员/架构师/产品经理 | 待修复/修复中/已验证 |
```

**问题修复流程**：

1. **程序员问题**：反馈给程序员修复 → 修复后重新测试
2. **架构问题**：反馈给架构师重新设计 → 重新开发 → 重新测试
3. **需求问题**：反馈给产品经理重新澄清 → 调整设计 → 重新开发

**修复验证**：
- 问题修复后，执行回归测试
- 验证问题已解决且未引入新问题

---

### 阶段三：测试报告与交付确认

**测试报告**：

写入 `/开发手册/5.开发进度日志.md` 对应步骤的"测试报告"部分：

```markdown
## 步骤X - 测试报告

### 测试时间
YYYY-MM-DD HH:mm

### 测试范围
- 功能模块：xxx
- 测试类型：功能/集成/性能/安全

### 测试执行摘要
| 测试项 | 用例数 | 通过 | 失败 | 跳过 |
|--------|--------|------|------|------|
| 功能测试 | 10 | 10 | 0 | 0 |
| 集成测试 | 5 | 5 | 0 | 0 |

### 问题统计
- 致命：0
- 严重：0
- 一般：0
- 建议：1

### 测试结论
通过 / 不通过

### 遗留问题
| 问题描述 | 计划处理时间 |
|----------|--------------|
|          |              |

### 交付物清单
- [x] 接口文档已更新
- [x] 开发进度日志已更新
- [x] 用户已确认本步「通过」后，代码已提交 Git（commit 格式见 [SKILL.md](../SKILL.md) 全局约束）
```

**用户确认**：
- 必须获得用户回复"通过"确认
- **在收到用户「通过」之前**，不得执行 `git commit`/推送（程序员阶段同样不得提前提交）
- 用户确认后方可：执行本步 **Git 提交**、更新《开发进度日志》中的 **Git Commit** 字段，并进入下一步开发或最终交付

---

## End 检查点

完成此角色时必须交付：

- [ ] 测试报告已写入《开发进度日志》
- [ ] 所有 P0/P1 级别问题已修复并验证
- [ ] `/开发手册/README.md` 已更新当前进度
- [ ] 已获得用户对本步的 **「通过」确认**
- [ ] 已在用户确认**之后**执行本步 `git commit`（及用户若要求的推送），并将 commit 信息记入《开发进度日志》对应步骤

---

## 输出至下一环节

**当前模块测试通过，还有下一步开发**：
- 引导至**程序员**角色，开始下一个模块的开发
- 如果下一步需要新的框架设计，由程序员角色触发架构师进行设计

**当前模块测试不通过，需要修复**：
- **代码缺陷** → 反馈给**程序员**修复
- **设计缺陷** → 反馈给**架构师**重新设计  
- **需求理解偏差** → 反馈给**产品经理**重新澄清

**全部开发完成**：
- 输出最终交付物清单
- 提供项目总结

---

## 回退场景

当发生以下情况时，需要回退至对应角色：

1. **发现功能缺陷**：回退至程序员修复
2. **发现设计缺陷**：回退至架构师重新设计
3. **发现需求理解偏差**：回退至产品经理重新澄清

**回退操作**：
- 明确问题类型和责任角色
- 标记当前测试状态为"待修复"
- 等待修复完成后重新执行测试
