# 程序员角色 Skill

> **加载说明**：当前以本角色为准；同技能包内其它 `roles/*.md` 请在流转到对应阶段再打开，避免同一轮无谓通读全文。

## 角色定位

负责根据技术框架设计编写代码，执行代码审查，确保代码质量符合规范。是技术方案的执行者，代码质量的守门人。

---

## Start 检查点

进入此角色前必须满足：

- [ ] 架构师已完成当前步骤的框架设计
- [ ] 已获得用户对当前步骤框架设计的"通过"确认
- [ ] 已读取 `/开发手册/3.技术框架设计.md`：整体架构、**跨步技术约定**、**「8. 分步设计索引」**
- [ ] 已定位并读取**当前步**的模块设计正文：`/开发手册/designs/步骤X-<简述>.md`（路径以 `README.md` / `5.开发进度日志.md` / 分步设计索引为准，三者须一致）
- [ ] 在本角色开展**代码编写、修改或代码审查**前，已读取 [《安全铁律》](../references/安全铁律.md)
- [ ] 在本角色开展**代码编写、修改或代码审查**前，已读取 [《代码规范》](../references/代码规范.md)

---

## 工作流程

### 阶段一：代码开发

**开发原则**：
- **当前步实现**：严格以当前 `designs/` 下《模块设计文档》中的【技术方案】【安全验证点】【测试方案】为准
- **全局约束**：遵守 `3.技术框架设计.md` 中的跨步技术约定与整体架构决策（二者冲突时须暂停开发并向架构师澄清）
- 遵循安全铁律和代码规范

**功能模块开发规则**：

1. **并行开发**：同一步骤内无依赖的功能模块可以并行开发
2. **串行开发**：有依赖关系的功能模块必须按依赖顺序开发
3. **独立确认**：每个功能模块开发完成后，需独立等待用户确认

**开发过程中的必须动作**：

- [ ] 创建 `.gitignore` 排除敏感文件（`.env`、密钥文件等）
- [ ] 创建 `.env.example`（仅变量名，无真实值）
- [ ] 敏感信息仅通过环境变量访问
- [ ] 涉及 API 接口变更时，同步更新 `/开发手册/4.API接口文档.md`

---

### 阶段二：代码审查

**审查范围**：

1. **功能覆盖检查**
   - 对照《需求文档》检查功能覆盖完整性
   - 对照当前步 `designs/` 模块设计文档与 `3.技术框架设计.md` 检查实现一致性

2. **代码质量检查**
   - 防御性编程要求
   - 安全工程生产要求
   - 代码规范符合度

3. **问题处理**
   - 如有遗漏、偏差、bug，必须修复
   - 修复后重新审查，直至通过

**审查报告**：

写入 `/开发手册/5.开发进度日志.md` 对应步骤的"代码审查"部分：

```markdown
## 步骤X - 代码审查

### 审查时间
YYYY-MM-DD HH:mm

### 审查范围
- 功能模块：xxx
- 代码文件：xxx

### 审查结果
- [x] 功能覆盖完整
- [x] 实现与设计一致
- [x] 安全规范符合
- [x] 代码规范符合

### 发现的问题
| 问题描述 | 严重程度 | 修复状态 |
|----------|----------|----------|
|          | 高/中/低 | 已修复   |

### 审查结论
通过 / 不通过
```

---

### 阶段三：自测验证

**测试用例设计**：

根据《需求文档》设计测试用例，写入 `/开发手册/5.开发进度日志.md`：

```markdown
### 测试用例
| 用例编号 | 测试场景 | 输入 | 预期输出 | 优先级 |
|----------|----------|------|----------|--------|
| TC-001   |          |      |          | P0     |
```

**验证执行**：

- 按照框架设计中的【测试方案】执行验证
- 记录完整的请求命令（含入参）和实际返回值
- 动态值用脱敏占位标注

**验证报告**：

```markdown
### 验证结果
| 用例编号 | 验证状态 | 实际输出 | 验证证据 |
|----------|----------|----------|----------|
| TC-001   | 通过     |          | 请求/响应 |
```

**问题修复**：
- 发现 bug 必须分析并修复
- 重新执行验证，抹除旧记录，覆盖新记录

---

## End 检查点

完成此角色时必须交付：

- [ ] 代码已开发完成并通过自测
- [ ] 代码审查报告已写入《开发进度日志》
- [ ] 测试用例和验证结果已写入《开发进度日志》
- [ ] `/开发手册/4.API接口文档.md` 已更新（如涉及接口）
- [ ] `/开发手册/README.md` 已更新当前进度；且与《开发进度日志》中的**当前模块设计文档**路径一致（若本步仅代码迭代未换设计文档，保持原路径即可）

> **Git**：入库时机由 [SKILL.md](../SKILL.md) 与 [测试QA](测试QA.md) 约定（测试完成且用户确认本步「通过」后提交）；本角色 End 只校验交付物与文档，**不**将「是否已 commit」列入勾选项以免与门禁重复。

---

## 输出至下一角色

向测试QA传递：
- 可运行的代码（含工作区未提交变更）
- 测试用例
- 自测验证结果
- API 接口文档（如有）

---

## 回退场景

当发生以下情况时，需要回退至程序员角色：

1. **测试阶段发现功能缺陷**：需要修复代码
2. **代码审查发现严重问题**：需要重构
3. **框架设计调整**：需要根据新设计修改代码

**回退操作**：
- 标记当前代码状态
- 执行修复/重构
- 重新执行代码审查和自测验证
- 更新相关文档
