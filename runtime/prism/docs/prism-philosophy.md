# Prism Philosophy

## One-Sentence Definition

Prism is the minimal heterogeneous AI opposition protocol for the main
executing AI. It prevents the main AI from replacing real completion with a
self-consistent story.

## What Prism Is

Prism is a deliberate source of cognitive resistance.

The main AI is good at building coherent narratives. That is useful when
planning and implementing, but dangerous when the same AI starts judging
whether its own work is complete. Prism exists to interrupt that self-approval
loop.

Prism should be invoked when the main AI may be:

- Overfitting to its own plan.
- Confusing mechanism with outcome.
- Treating evidence as completion.
- Narrowing the user's original intent.
- Avoiding a hard physical change by documenting a boundary.
- Creating new process artifacts to delay the real work.

## What Prism Is Not

Prism is not an acceptance ceremony.

It is not:

- A report generator.
- A receipt attachment.
- A multi-agent performance.
- A closeout requirement factory.
- A replacement for tests.
- A substitute for user judgment.
- A way for the main AI to outsource responsibility.

## The Core Question

Every Prism review ultimately returns to one question:

> Did the user's intended reality change, or did the system only produce a
> convincing explanation?

If the answer is "only explanation", Prism must return `concern` or `block`.

## The Three Duties

1. Expose the strongest objection.
2. Separate real-world change from self-consistent narrative.
3. Force the next step to be the smallest real correction, not another layer of
   governance.

## The Provider Shape

Prism is intentionally small and heterogenous:

- Kimi provides long-context archaeology, synthesis, and hidden-assumption
  pressure.
- Claude Code provides engineering review, implementation risk analysis, and
  concrete fix pressure.

No other provider belongs in this Prism.
