### L-170: 会话归属门要判定真实写动作，不能把“提到危险词”当作拥有任务
- **问题源**：Codex Stop hook 会话归属修复中，第一版 PreToolUse ownership claim 用宽泛正则扫描整条 Bash 命令。棱镜复核指出，`grep rm file.txt` 这类只是在搜索危险词的只读命令也可能被误判成写动作，从而错误声明当前 session 拥有任务，重新打开“普通讨论会话劫持 pending closeout”的风险。
- **解决方案**：把“是否声明任务所有权”从关键词扫描改为命令头解析：用 `shlex.split` 切分每段命令，只在真实命令头是 `rm/mv/cp/chmod/mkdir/touch/rmdir`、`git add/commit/mv/rm`、`sed -i`、`perl -pi` 或 Codex 原生写工具时声明所有权；同时覆盖 `sudo/env/timeout` 等常见 wrapper 和组合短参数。拒绝危险命令时必须先返回 deny JSON 并立即退出，不得继续声明所有权。
- **最后效果**：Stop hook 可以更可靠地区分“这个会话确实改了当前任务”与“这个会话只是读文件或讨论”。只读会话默认 advisory-only，不会驱动 Layer B 收尾；真实写会话会被记录并允许后续 Stop 收口。
- **适用边界**：适用于任何用生命周期 hook 绑定任务所有权的 Agent 宿主；不等同于完整 shell 沙箱，解释器内部删除、复杂脚本文件和远程命令仍需更强工具审计或显式任务边界。
