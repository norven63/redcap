### L-166: 收口重验必须有任务卡报告锚点兜底
- **问题源**：任务报告在首次提交时可以被 git diff、当前 report marker 或 pending closure artifact 找到；但 closeout / session-end 进入 zero-diff 重验时，报告不再出现在本次 diff，marker 可能已被清理，pending closure 又可能被后续 validator-chain 状态覆盖成空 artifact。此时如果 `task-report-check` 不回退读取 `.dev-task.md` 的 `task_report:`，就会把已经存在且模板完整的报告误判为缺失。
- **解决方案**：把 `.dev-task.md` 的 `task_report:` 作为第三层稳定锚点：marker 与 pending artifact 优先，二者缺席时使用任务卡锚点；同时保留 stale anchor 冲突检查，避免旧任务卡路径掩盖更新的报告。
- **最后效果**：SessionEnd、diagnose、current-status 或补救链路可以在任务已提交后的 zero-diff 窗口继续证明“本轮报告存在且有效”，不会因为运行时 marker 被清理而反复写入 `validator-chain` / `task-report` pending closure。
