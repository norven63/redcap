### L-164: 出包排除证据不能替代历史资产治理完成
- **问题源**：正式发布前，`workspace-state`、私有状态、草稿或密钥路径可以通过 `.npmignore` 和 package candidate 检查证明“不进入候选包”；但这类证据很容易被误读成“历史资产已经物理清理完成”。对于 `compass`、`references`、`prism`、`loom` 这类控制面、证据链或产品边界根目录，包面排除或候选数为 0 只说明没有暴露到包面，不能证明资产生命周期、考古锚点、迁移/回滚和产品边界已经完成。
- **解决方案**：把 R1 延期根目录按 release gate 的固定 disposition 分类：本地非历史状态只做 package absence 与 `.npmignore` 排除证明；真正的历史/产品根目录必须保持 `release-blocker-until-resolved`，直到有独立 tranche 给出迁移、公共晋升、保留或阻断的 receipt。严禁新增“package-visible but acceptable”之类的第五种灰色口径。
- **最后效果**：正式发布任务不能再用“没进包”冒充“历史资产已清理”。发布计划、检查脚本和 acceptance 会同时保护两层证据：防泄漏证据负责公开包安全，历史资产 disposition 负责长期治理完成度。
