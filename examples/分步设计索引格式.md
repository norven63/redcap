# 分步设计索引格式（用于 `3.技术框架设计.md`）

将以下内容作为 **`## 8. 分步设计索引`** 章节粘贴到《技术框架设计》中；随每步评审通过**追加行或更新状态**，勿把各步长篇方案正文写进本文件。

```markdown
## 8. 分步设计索引（随步骤推进持续更新）

| 步骤 | 模块设计文档 | 状态 | 备注 |
|------|--------------|------|------|
| 步骤1 | [./designs/步骤1-<简述>.md](./designs/步骤1-<简述>.md) | 待评审 / 已通过 | 与 README、开发进度日志中路径一致 |
| 步骤2 | [./designs/步骤2-<简述>.md](./designs/步骤2-<简述>.md) | 待评审 / 已通过 |  |
```

## 字段说明

| 列 | 说明 |
|----|------|
| **步骤** | 与「3. 开发步骤规划」表中步骤编号一致 |
| **模块设计文档** | 相对 `开发手册/` 的路径，建议使用 `./designs/步骤N-<简述>.md` |
| **状态** | 建议：`待评审` → 用户确认「通过」后改为 `已通过`；若作废可标 `已失效（原因）` |
| **备注** | 并行步骤、依赖其他设计文档等 |

## 一致性检查（每次更新索引后）

- [ ] `README.md`「当前模块设计文档」指向当前正在推进的那一行
- [ ] `5.开发进度日志.md` 当前步骤中的「模块设计文档」字段与本表一致
