# 模块设计文档格式（用于 `/开发手册/designs/步骤X-<简述>.md`）

每步（或可独立交付的模块）**一份文件**；正文全部在本文件中编写，**不要**再粘贴进 `3.技术框架设计.md`。

文件名示例：`步骤1-用户认证.md`、`步骤2-订单与支付.md`。

---

```markdown
# 步骤N：<模块或主题简述>

> 关联：`3.技术框架设计.md` → 「8. 分步设计索引」中对应行  
> 当前步技术方案以本文档为准；跨步约定以 `3.技术框架设计.md` 为准。

## 【本步目标】

- 交付物：<一句话说明本步结束时应具备的内容>

## 【技术方案】

- 关键目录/模块划分：
- 核心流程（可附 Mermaid 或伪代码）：
- 依赖的外部服务：<无则写「无」>
- 本步技术折中（如有）：<瓶颈与演进方向；可量化则写监控/阈值>

## 【需您准备】

- [ ] <项说明>（清单式、带复选框；格式与 redcap skill 的 `examples/需您准备格式.md` 一致）
- 无需人工准备时写：**无**

## 【安全验证点】

- 须完全遵守 redcap skill 的 `references/安全铁律.md`（**不在此重复细则**）

## 【测试方案】

| 验证项 | 预期结果 | 备注 |
|--------|----------|------|
|        |          |      |

## 【下一步】（必填）

- **下一模块设计文档**：`./designs/步骤N+1-<简述>.md`  
  - 若无后续分步设计：写 **无**；并写明接下来动作（例如：本步完成后 → 程序员自测 → 测试QA → 整体验收）
- **并行/依赖说明**（如有）：<例如与 `步骤1-b-xxx.md` 可并行，但依赖步骤1-a 完成>
```

---

## 与项目其它文档的同步

1. 新建或重大修改本文件后：更新 `3.技术框架设计.md` 中索引表的**链接与状态**。  
2. 进入开发与验证阶段：保证 `5.开发进度日志.md` **当前步骤**「模块设计文档」指向**当前**这份文件路径（**唯一信源**）；`README.md` 不重复写路径。
