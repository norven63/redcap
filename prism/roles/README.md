# 角色分配指南

> 棱镜的 Agent 角色分配原则。

---

## 核心原则

棱镜中的"角色"不是 RedCap Dispatcher 意义上的专业角色（PM/架构师/程序员），而是**分析视角的分配**。

- 每个 Agent 都是独立的"分析员"
- 视角分配在 Frame 步骤完成，写入问题包发送给对应 Agent
- 模型选择比视角分配更重要——不同模型 = 不同认知偏见 = 真正独立的视角

---

## 模型组合建议

| 场景 | 推荐组合 |
|------|---------|
| 标准探索（3人） | Sonnet + Haiku + Opus |
| 红队（跨家族） | Sonnet + Haiku + GPT-4.1 |
| 深度议事（4人） | Sonnet × 2 + Opus + GPT-4.1 |
| 复活测试（4人） | Sonnet + Haiku + Opus + GPT-4.1 |

**跨家族红线**：redteam 模式必须包含 ≥1 个跨家族模型（Claude 系 vs GPT 系）。

---

## 视角库（explore 模式使用）

按需从以下视角中选 3~5 个分配：

- **架构师**：可扩展性、模块边界、依赖关系
- **实践者**：落地难度、实现代价、已知坑
- **用户**：调用方体验、文档完整性、心智负担
- **批评者**：假设前提合理性、遗漏场景
- **综合者**：跨方案对比、最优路径

---

## 重要提醒

- 一个 Agent 只分配一个视角
- 所有 Agent 收到的**问题陈述完全相同**（视角偏重不同）
- council 模式第一轮遵循 Dispatch Firewall，后续轮可共享前轮摘要
