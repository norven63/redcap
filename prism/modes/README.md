# 模式选择指南

> 先选协议族，再选模式。

---

## 协议族 → 模式 映射

```
独立取样协议
  ├─ explore   开放探索，方向未定，收集多角度见解
  ├─ redteam   对抗性审查，寻找风险和漏洞
  └─ test      结构化评分，验证预期行为/设计

议事协议
  └─ council   多轮讨论，迭代收敛，解决分歧
```

---

## 选择决策树

```
有明确的评分/验收标准？
  ├─ YES → test
  └─ NO
        想找反对意见和风险？
          ├─ YES → redteam
          └─ NO
                存在互斥方案或分歧？
                  ├─ YES → council
                  └─ NO → explore
```

---

## 各模式快速参考

| 模式 | 典型场景 | Agent 数 | 协议族 |
|------|---------|---------|--------|
| [explore](explore.md) | 架构方向探索、新功能可行性 | 3~5 | 独立取样 |
| [redteam](redteam.md) | 核心协议改动前审查、安全性检查 | 3~5（含跨家族） | 独立取样 |
| [test](test.md) | soul/identity 改动后验证、复活协议测试 | 2~4 | 独立取样 |
| [council](../protocol.md#二议事协议council-protocol) | 方案分歧、卡壳超过 2 轮 | 3~5 | 议事 |
