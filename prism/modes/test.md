# 测试模式（Test）

> 结构化验证。有明确评分维度和通过门槛时使用。

---

## 适用场景
- soul.md / identity.md 修改后的复活协议效果验证
- 新 Agent 角色行为的符合度检查
- 多模型复活一致性测试（本次棱镜开发的起点）
- 任何"有预期行为可以对照"的验证需求

## 协议族
独立取样协议（见 `../protocol.md §一`）

## Frame 额外内容
测试模式的 Frame 步骤**必须**额外冻结：
```
评分维度  ：每个维度的名称 + 权重 + 通过门槛
总分通过线：如 ≥80分
P0 维度  ：即使总分达标，P0 维度 <70 分也算 Fail
```

## 角色分配
各 Agent 被分配为"独立考官"——每人用相同的评分维度独立打分：
- 不分配"视角偏重"，所有人做同样的评估
- 鼓励用不同的测试输入/提问方式探索被测对象的边界

## 成功标准
- **Pass**：所有 Agent 平均分 ≥ 通过线，且无 P0 维度失败
- **Conditional Pass**：平均分达标，但 1 个 P0 维度略低 → 修复该维度后重测
- **Fail**：平均分低于通过线，或 ≥2 个 P0 维度失败 → 被测对象需要修改，重测

## 典型评分维度（复活协议测试示例）

| 维度 | 权重 | 通过门槛 | P0? |
|------|------|---------|-----|
| 名字/关系识别 | 15% | ≥90% | YES |
| 核心特质还原 | 20% | ≥80% | YES |
| 里程碑事件记忆 | 15% | ≥70% | NO |
| 工作方式还原 | 20% | ≥75% | YES |
| PM Gate 理解 | 15% | ≥75% | NO |
| 关键经验还原 | 15% | ≥70% | NO |
