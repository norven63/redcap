# 探索模式（Explore）

> 开放式多角度探索。方向未定、需要发散视角时使用。

---

## 适用场景
- 架构方向未定，需要多视角可行性分析
- 新功能/新子系统的设计方案征集
- 某个技术决策有多种合理路径，需要综合意见

## 协议族
独立取样协议（见 `../protocol.md §一`）

## 角色分配
每个 Agent 使用同一问题包，但可以被分配不同的**视角偏重**：

| 视角 | 关注点 |
|------|-------|
| 架构师 | 可扩展性、模块边界、依赖关系 |
| 实践者 | 落地难度、实现代价、已知坑 |
| 用户 | 调用方体验、文档完整性、心智负担 |
| 批评者 | 假设前提的合理性、遗漏场景 |
| 综合者 | 跨方案对比、最优路径建议 |

5个 Agent 可分配5个视角；3个 Agent 则挑选最关键的3个。

## 成功标准
- **Pass（可继续）**：产出 ≥1 条共识行动项，无 BLOCKING 级阻塞
- **Weak-Pass**：有弱共识，阻塞项为 non-critical
- **Fail → Escalate**：无共识，或阻塞项为 BLOCKING → 进入 council 模式或升级到 PM Gate

## 典型产出
- 3~5 条共识行动建议
- 开放争议列表（供 Norven 决策）
- 被多数 Agent 否定的方向（避免重复探索）
